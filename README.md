# СтройГрад — обращения жителей

Два связанных приложения на вымышленных данных: **кабинет управляющей компании** и **кабинет жильца**. Общая серверная очередь, назначение подразделений, статусы, уточнения и история действий. Проект задания №2 «Скаутби».

## Открыть приложения

| Кабинет | Что можно делать | Ссылка |
|---|---|---|
| Управляющая компания | Разбирать очередь, назначать подразделения, менять статусы и оставлять комментарии | [Открыть УК](https://scoutby-research-uk-oct26.dmitryga.chatgpt.site/uk.html) |
| Житель | Отправить обращение, получить персональную ссылку, следить за статусом и отвечать УК | [Открыть кабинет жильца](https://scoutby-research-uk-oct26.dmitryga.chatgpt.site/resident.html) |
| Справочник УК | 10 категорий и 6 подразделений с правилами направления | [Категории и адресаты](https://scoutby-research-uk-oct26.dmitryga.chatgpt.site/uk.html#catalog) |
| Исследование | 150 обращений, сравнение двух способов разбора и предварительный аудит | [Открыть исследование](https://scoutby-research-uk-oct26.dmitryga.chatgpt.site/research/index.html) |

Посетителям **не нужны GPT, Google, аккаунт GitHub или установка программ**. Репозиторий открыт для просмотра, клонирования и загрузки исходников. Работающие приложения и их общая база остаются на публичном хостинге по ссылкам выше; перенос кода в GitHub не переносит базу автоматически.

## Возможности

- Рабочий дашборд УК, поиск и фильтры, приоритет аварий, групповые назначения и экспорт CSV.
- Отдельный интерфейс жильца: подача заявки, отслеживание по ссылке, уточнения и история.
- Общая D1-база: изменения доступны с разных устройств.
- Проверка аварийного маршрута и защита от одновременной перезаписи карточки.
- Начальные данные: 150 обезличенных вымышленных обращений. Учётные записи жильцов и реальные персональные данные не используются.
- Адаптивное отображение для телефона и большого экрана.

## Запустить свою копию

Нужны Node.js >=22.13 и npm:

```sh
git clone https://github.com/dgolovin1990-glitch/scoutby-requests.git
cd scoutby-requests
npm ci
npm run build
npm run configure:local
npm run db:local
npm run start:standalone -- --port 8789
```

Откройте `http://127.0.0.1:8789/uk.html` и `http://127.0.0.1:8789/resident.html`. Локальная база независима от опубликованной.

Для самостоятельной публикации с общей базой на своём Cloudflare подготовлены команды `configure:cloudflare`, `db:remote`, `deploy:cloudflare`. Владельцу потребуются собственная D1-база и доступ Cloudflare; посетителям — только полученная ссылка. Подробно: [инструкция по запуску и публикации](docs/DEPLOYMENT.md).

GitHub Pages не запускает серверную часть этого приложения. Готовая независимая публикация `workers.dev` из GitHub пока не настроена: ключи внешнего аккаунта в репозитории отсутствуют.

## Проверено

На опубликованной версии пройдены 15/15 сквозных серверных сценариев без аккаунта: подача → появление в очереди УК → назначение → статус жильца → уточнение → закрытие. Отдельно проверены неверный персональный ключ, аварийный маршрут и конфликт версий. [Отчёты проверок](docs/verification/).

Исследовательские показатели A/B — согласованность с предварительной разметкой того же ИИ, а не независимая точность. Разбор новых заявок предлагает алгоритм правил; диспетчер должен его проверить.

## История и ограничения

Оригинальные Git-коммиты с точными SHA сохранены в `docs/source-history.bundle`; [история происхождения](docs/HISTORY.md) объясняет импорт снимков в GitHub. Личная переписка, ключи, cookies и рабочая база в репозиторий не включены.

Это учебный публичный прототип: любой посетитель может попробовать роль УК. Для реальной эксплуатации нужны права сотрудников и интеграции со службами. Приложение фиксирует назначение в системе, но не отправляет сообщения в реальные службы. Используйте только вымышленные обращения без персональных данных.
